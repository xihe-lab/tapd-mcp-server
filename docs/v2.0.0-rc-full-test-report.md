## 2. 缺陷台账

### D8 — wiki 富文本服务端透传假设不成立（2.0 特有，已修复闭环）

- **现象**: SERVER_MD_TOOLS 架构假设 TAPD `/tapd_wikis` 服务端渲染 markdown_description，curl 直调实证服务端不渲染（description 恒空），wiki 正文闭环断（数据无损）。
- **证据**: curl 直调 `/tapd_wikis`（带 creator）创建后 GET 读回 description 空、markdown_description 存 md 原文；/wikis 端点为另一权限域（403）。
- **修复**（鲁班 410835b/c3471fe/45c3c5c，已 fast-forward 合入 feature/2.0-monorepo → 45c3c5c）:
  - 架构改 `DUAL_WRITE_TOOLS`：wiki description 客户端 markdownIt 渲染存 HTML + markdown_description 存 md 原文（双写）
  - create 拆两段调用，规避 TAPD 服务端同传丢 description
  - 读侧 walk 加存量 wiki 回填：description 空且 markdown_description 有值时补正文（旧数据闭环）
- **验证三件套**: ①20 号反向回归 23/0（双写 create/update 正面断言 + AUTO 读回 turndown 化 + 存量回填静态断言）②19 号 wiki create/update 复验 6/0（双写两字段 + modifier=徐昭 正确写入）③单测（45c3c5c，双写/两阶段/存量 fallback）
- **定级**: 一般级（不阻塞 rc）→ 已修复，回归资产固化于 20 号脚本

### 观察项（非缺陷）

1. **story_fields_info 302**: TAPD 端点对该凭证返回 302 登录页（curl 直带有效 token 实证），服务端行为，非 rc 缺陷。
2. **SDK_DISABLED fallback 代理差异**: fallback 路径（undici fetch）不走系统代理 env；SDK 默认路径代理逻辑正常。本机免沙箱直连实测不受影响；生产依赖系统代理出网的环境需注意此差异。
3. **batch_fetch 数组边界**: 不安全 number 数组形态不报 guard 错（guard 已知边界），查询不命中任何实体，无静默错数。
4. **update_wiki NICK_NAME 引导**: 未设 TAPD_NICK_NAME 时返回友好引导文案（正确防御行为，非缺陷）。
5. **create_wiki description 落 markdown_description**（修复前观察）: 已随 D8 修复被双写架构取代。
